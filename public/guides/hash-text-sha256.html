How to hash text with SHA-256 in the browser

Dev Tools can hash a string with the Web Crypto API in this tab and return a hex digest. FileTools Kit does not send that string to a hashing server. Use it to compare a line you already have with a digest someone published. It is not a password store.

Hash versus encoding

SHA-256 is a one-way digest. You cannot turn the hex back into the text. Base64 is encoding. Anyone can decode Base64. Do not treat either one as encryption, and do not paste a live password on a shared screen. This page does not offer MD5.

A single browser hash is not a design for storing passwords. Password storage needs a slow hash and a salt, which this tool does not set up.

Steps

  1. Open Dev Tools.
  2. Paste the input. A trailing space changes the digest.
  3. Press Generate. The page shows SHA-1, SHA-256, SHA-384, and SHA-512 together. Copy the SHA-256 line.
  4. Compare it with the digest you were given. A mismatch means the text is not the same, not that the tool "failed".

Why two digests differ

The text is encoded as UTF-8 before hashing, which is what most command-line tools and libraries do. A mismatch almost always comes from characters you cannot see: a trailing newline (the shell command echo adds one unless you use echo -n), Windows line endings versus Unix ones, a non-breaking space pasted from a web page, or curly quotes from a word processor. Check those before anything else.

To test the page itself, hash the three letters abc with nothing after them. SHA-256 should start ba7816bf and end f20015ad. That value is the published test vector for SHA-256, so a match means the hashing is right and any other mismatch is in the input.

Reading the output

Output is lowercase hex. SHA-256 gives 64 characters, SHA-1 gives 40, SHA-384 gives 96, and SHA-512 gives 128. Compare the whole string, not the first few characters. SHA-1 is shown for checking old checksums. It is no longer considered safe against deliberate collisions, so do not choose it for anything new.
