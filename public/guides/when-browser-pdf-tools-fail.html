When browser PDF tools fail

Last updated: 1 October 2026 · Written by Souren Das, FileTools Kit, Bengaluru. These notes describe the tools on this site, including what they cannot do.

In-tab PDF tools fail in a handful of repeatable ways. This page is the list I use when a file opens in Adobe and does nothing useful in FileTools Kit. It is not a claim that a server uploader would succeed, only a map of the limits of pdf-lib and the canvas in a normal browser tab.

Encryption

If the PDF asks for a password, the suite often cannot read the page stream. ignoreEncryption is a best effort. It does not unlock every file. Remove the password in a reader you trust, export an unlocked copy, then run the job on that copy. Do not email the password to this site. There is nowhere to send it.

Memory

A phone tab will stall on a stack of camera scans. Merge or rasterize in batches. Close other tabs. If the tab crashes, the in-memory files are gone; the originals on disk are not, unless you overwrote them.

Signatures and forms

Copying pages can invalidate a digital signature even when the page looks the same. Form fields may survive a simple merge and may not survive a raster export. If you need a signed original intact, do not run it through a rewrite. Send the original and a separate attachment.

Scans and OCR

A photo of a page is not text. Split, merge, and compress will not make it searchable. PDF to JPG makes another picture. If a portal wants selectable text, you need OCR elsewhere, and you should know that product’s upload policy.

Weird PDFs

Some files use features pdf-lib does not implement. The practical workaround is to open the file in a reader and print to a new PDF, then retry. That flattens some problems and can also flatten things you wanted kept, such as layers. Check the new file.

What I would not do

I would not upload a passport or an unreleased contract to a random compress site to “see if it works.” If this tab cannot open it, use a desktop tool on the machine you already trust, or ask the sender for an unlocked export.

A short decision list

File asks for a password: stop, unlock elsewhere, retry. Tab fans the laptop: batch the job. Need searchable text: this site will not OCR. Need the signature to stay valid: do not rewrite. Need the file under a tiny cap and it is a scan: image optimizer, then JPG to PDF. Need true redaction: not here.

If you hit two of those at once, split the problem. Unlock first. Then shrink. Then send. Doing all three in one online uploader is how a sensitive file ends up on someone else’s disk for a job this tab could have done in pieces.

I would rather the button error than invent a success. An error means the original is still the file you have. A fake “compressed” download that is the same bytes with a new name wastes the afternoon.
