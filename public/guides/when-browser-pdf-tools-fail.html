When browser PDF tools fail

Last updated 10 October 2026 · Written by Souren Das

In-tab PDF tools fail in a handful of repeatable ways. This page is the list I use when a file opens fine in a PDF reader and does nothing useful in FileTools Kit. It is not a claim that a server uploader would succeed, only a map of the limits of pdf-lib, PDF.js, and the canvas in a normal browser tab, with the message you are likely to see and the fix for each.

Encryption

If the PDF asks for a password, or has restrictions set by its creator, the tools often cannot read or rebuild it. You may see messages such as "Merge failed", "Split failed. Encrypted PDFs may fail", "Could not compress that file. Encrypted PDFs often fail", or "Encrypted PDFs cannot be reorganized here." Password Protect refuses with "This PDF already has a password."

Fix: open the file in a reader that can unlock it (you need the password), then save or print an unlocked copy, and run the job on that copy. Bank statements and e-filing documents are common examples. Do not email the password to this site; there is nowhere to send it.

Memory

Everything happens in the tab's memory. A stack of phone scans, each page a 4 MB image, can exhaust a phone browser or an older laptop. Symptoms: the page freezes, the fan spins, or the tab reloads by itself. Thumbnails in Organize PDF warn above 150 pages, and PDF to JPG warns above 50.

Fix: work in batches. Split a long file into parts, process each, and merge them back. Close other heavy tabs. Use a lower resolution in PDF to JPG. If the tab crashes, the in-memory files are gone; the originals on disk are not, unless you overwrote them.

Signatures and forms

Copying pages into a new document invalidates a digital signature, even when the page looks identical, because the signature covers the exact bytes of the original file. Form fields may survive a simple merge and may not; they do not survive PDF to JPG, which makes pictures.

Fix: if a signed original must stay valid, do not run it through any rewrite. Send it as is, as a separate attachment. Fill forms before merging, and check the merged file.

Scans and OCR

A photo of a page is not text. Split, merge, and compress will not make it searchable. PDF to JPG makes another picture. If a portal wants selectable text, you need OCR elsewhere, and you should know that product's upload policy before handing it a sensitive scan.

Size that will not come down

Compress PDF is a light structural rewrite. It does not recompress images, so a scanned PDF rarely shrinks. This is the most common "failure", and it is really a mismatch between job and tool.

Fix: rebuild the scan from smaller images: PDF to JPG at Screen or Standard, shrink in Image Optimizer, then JPG to PDF. Full steps in getting a PDF under 1 MB or 200 KB.

Odd or damaged PDFs

Some files use features pdf-lib does not implement, or are slightly broken in ways a desktop reader quietly tolerates. You may see "Could not read that PDF" or a download that opens blank.

Fix: open the file in a reader and print to a new PDF (the "Save as PDF" or "Microsoft Print to PDF" printer), then retry with the new file. That flattens many problems. It can also flatten things you wanted kept, such as layers, links, and form fields, so check the new file.

Things this site does not do at all

Some requests are not failures, just not offered: redaction, OCR, editing text inside a PDF, removing a password, converting PDF to Word, and filling forms. For these, use desktop software you trust. The watermark, password, and redaction guide explains why a black box is not redaction.

A short decision list

  • File asks for a password: stop, unlock elsewhere, retry.
  • Tab freezes: batch the job.
  • Need searchable text: this site will not OCR.
  • Need the signature to stay valid: do not rewrite.
  • Need the file under a tiny cap and it is a scan: Image Optimizer, then JPG to PDF.
  • Need true redaction: not here.

If you hit two at once, split the problem. Unlock first. Then shrink. Then send.

What I would not do

I would not upload a passport or an unreleased contract to a random compress site to see if it works. If this tab cannot open a file, use a desktop tool on a machine you already trust, or ask the sender for an unlocked export. I would also rather a button show an error than invent a success: an error means the original is still the file you have, while a fake "compressed" download that is the same bytes with a new name wastes an afternoon.

FAQ

Will a reload fix a stuck job?

It clears the tab and everything loaded in it. Pick the files again, in smaller batches.

Does a different browser help?

Sometimes. Current Chrome, Edge, Firefox, and Safari all run these tools; a desktop browser has more memory than a phone.

How do I report a file that fails?

Email support@filetoolskit.com with the tool, the browser, and the error text. Do not attach a sensitive document.
