What “files stay in this tab” means

Last updated 10 October 2026 · Written by Souren Das

Every tool page on FileTools Kit says some version of "files stay in this tab". This page explains exactly what that sentence covers, what it does not, and how you can check it yourself instead of taking my word for it.

In short: the PDF, image, or resume you pick is read as a browser File object and processed by JavaScript on your device. FileTools Kit does not run an upload API that receives those bytes. Closing the tab drops the in-memory copy. It does not delete a download you already saved.

Why the site is built this way

Most online PDF and image tools upload your file to a server, process it there, and send it back. That works, but it means a stranger's computer holds your payslip or ID scan for a while, under a retention policy you have to trust. Modern browsers can do much of this work themselves: pdf-lib edits PDFs, PDF.js draws pages, the canvas re-encodes images, and Web Crypto hashes and encrypts. Doing the job in the tab removes the upload step entirely. The cost is that a phone or an old laptop has less memory than a server, which is why very large scans can stall here.

What happens tool by tool

  • PDF tools (merge, split, compress, organize, page numbers, password, PDF to JPG): the file is read into memory, rebuilt with pdf-lib or drawn with PDF.js, and the result is handed to your browser as a download.
  • Image tools (Image Optimizer, File Converter, SVG Studio, Social Studio): images are drawn on a canvas and re-encoded locally.
  • Resume Builder: the form and the PDF are built in the tab, and a draft is saved in your browser's localStorage.
  • Text and data tools (Dev Tools, Markdown Editor, Text Diff): the text stays in the page.
  • Calculators: the health and currency calculators run on numbers in the page. The currency rates are reference values built into the page, not fetched live.

What still leaves the device

Loading the website does. The host, Vercel, can see your IP address, user agent, the URL, referrer, and time, the way any HTTPS host can. Vercel Web Analytics may record a page view and route. That is not your PDF. Google AdSense may set cookies and measure ads; the publisher ID is in ads.txt (pub-4409273905876536). Ad code does not receive file bytes from our servers, because we do not have those bytes.

A few assets load from third parties: Google AdSense scripts and ads, and two directory badge images (directree.io and launchllama.co). Those are requests for the asset, not an upload of your document. Details are in the privacy policy and cookie policy.

What stays in your browser

  • The File objects for PDFs and images, until you close or reload the tab.
  • An optional resume draft in localStorage (ftk_resume_v1) if you used the builder and did not clear site data.
  • Layout-test keys (ftk_ab_*): a random ID and which page variant you saw. They are not sent to us.

How to check it yourself

You do not have to trust this page. On a desktop browser:

  1. Open a tool, for example Merge PDF.
  2. Open the developer tools (F12, or right-click and Inspect) and choose the Network tab.
  3. Load a PDF and run the job.
  4. Look through the requests that appear. You will see page assets, analytics, and ad requests, but no request that carries your PDF to a FileTools Kit endpoint. The request sizes give it away: a 5 MB upload would show up as a 5 MB request.

A second check: open a tool page and run one small job so the tool’s code has loaded, then turn off Wi-Fi and run the job again on another file. The PDF and image tools keep working, because the work does not need the network once the page and its code are in the tab.

What this sentence does not mean

It does not mean the site is invisible. It does not mean a download is encrypted on your disk. It does not mean other sites you then upload the result to will keep it private. It does not mean encrypted PDFs will open. It does not mean health numbers or currency examples are professional advice.

A reload is a wipe

Refresh the tab and the File objects are gone. The download in your Downloads folder remains. People lose work by refreshing to "fix" a stall and then looking for the PDF in the page. It is not there. Pick the files again from disk.

Private browsing still processes locally, and it is more likely to drop the resume draft when the window closes. Do not rely on localStorage on a shared computer; export the PDF and take it with you, and clear site data when you are done.

Extensions can still read the page. A password manager, a grammar checker, or a screenshot tool is outside this site's control. "In this tab" is about our servers, not about every extension you installed.

FAQ

Do you keep logs of my files?

There is nothing to log. The files never reach a FileTools Kit server.

Is it safe for Aadhaar or PAN scans?

The processing is local. What happens to the result depends on where you send it next.

How do I delete the resume draft?

Clear this site's data in your browser settings.
